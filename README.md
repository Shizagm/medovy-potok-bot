# «Медовый поток» · бот Роя 0.9

Windows и Linux, Python 3.11+. Для портретов требуется Pillow из requirements.txt.
Dockerfile устанавливает пакет автоматически; Windows START_BOT.bat проверяет его. Код содержит игровые домашние правила клуба «Феникс».

**Закрытые карточки и выкуп у Шизы 0.7:** CHARACTERS.md.
**Рой, лавка и копилка:** ROY_AND_SHOP.md.
**Оформление и меню:** DESIGN.txt.
**Визуальный пример:** DESIGN_PREVIEW.html (демонстрационные данные).
**Для обновления работающего бота:** DESIGN.txt и UPGRADE.txt.
**Первый запуск на Windows:** START_HERE.txt, CONFIGURE.bat, START_BOT.bat.
**Самостоятельный покер:** POKER_RULES.md.

Бот работает через polling: публичный IP, домен, HTTPS-сертификат и открытые
порты на роутере не нужны. Компьютер должен работать без сна и иметь доступ
к api.telegram.org. Бот не хранит токен в опубликованном архиве. Введите его
локально через CONFIGURE.bat; настройки остаются в .env.

**Жетоны, занятые клетки и НПС 0.9:** TOKENS.md.
**Карта и передвижение:** MAPS.md. Начальная схема тестовая; режимы включаются мастером.

## Возможности

- Закрытые характеристики, подтверждение мастером и сведения Роя за 500 зм.
- Призраки без действий и сделок; выкуп за 1000 зм и временный штраф к проверкам.

- Один персонаж на аккаунт Telegram, регистрация /register Имя | Отряд с
  одобрением мастером /admit ID. Начальный баланс нулевой, сумму задаёт мастер.
- Кошелёк, сундук, хранение у Роя; журнал, три рейтинга и ручная сверка.
- Вдохновение 0/1 с подписью у имени; новое не накапливается при имеющемся.
- Один основной ход за визит; после него одно дополнительное действие за
  Вдохновение. /visit ID выдаётся мастером один раз в календарный день.
- Заявки действий, одобрение и проверка d20 с результатом в журнале.
- Сделки: оба подтверждают, мастер проверяет настенную карту и исполняет.
  Золото/предметы резервируются после двух согласий. Передача атомарная.
- Самостоятельный покер: вызов, согласование ставки, до двух перебросов,
  закрытые руки, фиксация, вскрытие и автоматическая выплата. Не тратит действие.
- Аренда, вместимость сундуков, питание, недельный расчёт, кладбище.
- Закрытые проверки кражи, обнаружение по Скрытности, автоматический перенос золота.
- Резервные копии SQLite и сохранение состояния после перезапуска.

## Команды игроков

Все личные данные и операции, кроме публичных столов покера и кнопки d20,
в личной переписке. Игрок должен сначала нажать /start у бота.

```text
/profile
/character
/dossiers
/resurrect
/register Торин | Первый отряд
/ratings
/archive 2026-11
/act base | Осматриваю кухню
/act inspiration | Читаю надпись
/rent 1
/storage in 100
/storage out 50
/spend 50 | Угощение гостям
/trade ID 100 0 - 12 | Покупка предмета №12 за 100 зм
/request НОМЕР
/cancel НОМЕР
/history
/poker
```

В trade после ID идут: отдаваемое золото, получаемое золото, мои предметы,
его предметы. Предметы — номера через запятую или дефис. Условия не меняются:
для изменений отменить и создать новое предложение. Вдохновение не передаётся.
Положение токенов проверяет мастер; бот не хранит координаты карты.

## Команды мастера

Меню мастера доступно через /admin. Текстовый список — /admin commands. Значения ID и НОМЕР в примерах нужно заменять.

```text
/players
/inspect ID
/pending
/admit ID
/approve НОМЕР
/reject НОМЕР
/visit ID
/inspire ID 1
/inspire ID 0
/gold ID delta 200 income | Награда за миссию
/gold ID delta -50 expense | Расход
/gold ID set 1000 none | Сверка кошелька
/rankfix ID 100 -50 | Исправление рейтингов
/item ID | Кольцо защиты
/askroll НОМЕР 3 14
/check НОМЕР 3 14
/record НОМЕР 12 3 14
/settle
/reclaim ID
/dead ID 1
/hp ID ЗДОРОВЬЕ
/pause ID 1
/pause ID 0
/notice Текст объявления Роя
/publish
/audit ID
/backup
/sync
```

Где `income` — учесть положительное начисление в заработке, `expense` — учесть
списание в расходах, `none` — изменить только деньги. /gold set устанавливает
только кошелёк; не включает сундук, деньги у Роя и текущую ставку покера.
/rankfix меняет только доход/расход за текущий месяц, а не реальные деньги.

В /record сначала натуральный кубик (1–20), затем модификатор, затем сложность.
Бросок за столом, кнопка игрока /askroll и мастерский /check используют одну
сохранённую проверку: повторно бросить по той же заявке нельзя. Одобрение заявки
расходует действие; бросок отдельно действия не требует. Преимущество/помеха и
боевые ресурсы остаются на усмотрении мастера, без автоматизации.

## Жильё и деньги

| Жильё | Сундук | Аренда за сутки | За неделю с едой |
|---|---:|---:|---:|
| Общий зал | Нет | 0 зм | 7 зм |
| Койка | 1000 зм | 20 зм | 147 зм |
| Отдельная комната | 5000 зм | 50 зм | 357 зм |
| Большая комната | 10000 зм | 100 зм | 707 зм |

Тариф одобряет мастер по карте. Свободные комнаты и соседство не проверяются
автоматически. Перед снижением тарифа освободи сундук до нового лимита.
В понедельник по Екатеринбургу списываются прошедшие дни до понедельника,
не включая его. /settle рассчитывает до сегодняшнего дня; повторно деньги за
те же дни не списываются. При смене тарифа старые дни сначала рассчитываются.
После простоя пропущенные дни учитываются. Питание живого — 1 зм/день.
Призракам питание не начисляется, аренда продолжается. Мастерская пауза
останавливает новые начисления, но сначала рассчитывает уже прошедшие дни.

Сначала платит кошелёк, затем сундук. Если на полную аренду денег нет, она
прекращается, остаток сундука хранится у Роя. Долг не накапливается; питание
снимается в пределах доступных монет. /reclaim возвращает хранимое в кошелёк.
Незавершённые сделки и вызовы отменяются при сверке, кражах и расчёте постоя,
если меняются доступные средства. Уже начатый покер не затрагивается: банк
отделён от кошельков и сундуков до результата.

## Рейтинги

- Самые богатые: кошелёк + сундук + хранение у Роя + собственная ставка в
  незавершённом покере. Артефакты не оцениваются.
- Заработок месяца: подтверждённые новые награды, кражи, чистый выигрыш покера.
- Гуляка: подтверждённые покупки, подарки золотом, аренда/еда, проигрыш покера.

Обычная продажа/получение подарка не увеличивает заработок месяца. Ничья и
возврат покерной ставки не создают доход/расход. Деньги из кампаний учитываются
только один раз; старые накопления вводи с none. Круговые операции ради таблиц
мастер исправляет через /rankfix. По одному остатку нельзя определить доход:
при сверке отдельно выясняй заработанное, потраченное и уже учтённое в боте.

Публичный снимок — раз в неделю, после расчёта постоя; /ratings показывает его.
/publish обновляет раньше и может помочь догадаться о краже по изменению сумм.
Месячные записи не стираются. Часовой пояс — Екатеринбург, при отсутствии IANA
на Windows используется текущий фиксированный UTC+5.

## Кражи

```text
/rob ВОР ЖЕРТВА wallet 30 5 7 2 14
```

После суммы: модификаторы Скрытности, Ловкости рук и Внимательности жертвы,
затем сложность кражи. Источник wallet/chest. Вместо Скрытности — none для
автоматического обнаружения. Скрытность должна быть строго выше пассивного Восприятия жертвы; иначе вор обнаружен.
При пройденном пороге Внимательность >= итоговой Скрытности раскрывает
вора, Ловкость рук >= сложности даёт добычу. Бот тратит основное действие.
Не трать его заранее через /act. Из кошелька можно взять до 10%, максимум 50 зм;
из сундука — до 20%. Одна успешная кража у жертвы за 30 дней. Дверь и замок
мастер разрешает отдельными действиями. Одежду передаёт вручную; оружие и
артефакты — только добровольной сделкой. Результаты кражи закрыты от группы.

## Linux / Docker

```bash
cp .env.example .env
# Заполнить BOT_TOKEN, ADMIN_IDS, TAVERN_CHAT_ID в редакторе
chmod 600 .env
python3.11 -m pip install -r requirements.txt
python3.11 bot.py
```

Для Docker с постоянным volume:

```bash
docker compose up -d --build
```

PUBLIC_TOPIC_ID — номер темы внутри закрытой группы; 0 — общий раздел.
В Telegram-группе боту нужно право управления тегами. Если Telegram не даёт
поставить тег администратору, Вдохновение всё равно остаётся в /profile.

## Хранение и восстановление

Папка data содержит базу и резервные копии. Не публикуй её и .env. Не запускай
одновременно два экземпляра с одним токеном. Не копируй только основной .sqlite3
работающего бота: часть данных может быть в WAL. /backup использует SQLite Backup API.
Для восстановления сначала останови процесс, сохрани текущую папку и восстанови
проверенную копию. В Docker не используй down -v без намерения удалить все данные.

Уведомления идут через сохраняемую очередь. При сбое текст может прийти повторно,
но финансовая операция не повторяется. Неполученные личные карточки остаются
в очереди, если игрок заблокировал бота. Вызов /pokerview повторно открывает руку.
Автоматических внешних копий и удаления старых локальных копий пока нет.
